# olo-like 开发指南

## 第一次运行

只想玩不必安装开发环境：[离线试玩页](../offline.html) 已内嵌 Cocos 引擎、脚本和场景。修改游戏则用 **Creator 3.8.6 打开仓库根目录**，等资源导入完毕，再打开 [Game.scene](../assets/Game.scene)。场景里的棋盘、摄像机和圆片在运行时创建，看效果请点击预览。改名或移动目录后，需要在 Creator 或微信开发者工具中按新路径重新导入。

构建需要 Node.js 和 npm（本项目验证环境为 Node.js 22），没有需单独安装的 npm 依赖。微信开发者工具只用于导入和调试微信包，不是网页构建的前置条件。

## 一次出手经过哪些代码

| 位置 | 职责与修改入口 |
| --- | --- |
| [GameScene.ts](../assets/scripts/GameScene.ts) | 创建正交相机与棋盘节点，将触摸位置换算为棋盘坐标；将画圆、画矩形和文字指令转换为 Cocos Graphics / Label，并处理窗口变更、前后台和触摸取消。 |
| [Table.ts](../assets/scripts/Table.ts) | 判断是否按中当前圆片，记录最近的手势采样；松手或拖到白区边界时将速度传给规则层。配色、白环、发射光圈、库存小点、帮助和结算画面均在这里。 |
| [Match.ts](../assets/scripts/Match.ts) | 不依赖 Cocos。管理双方队列、发射、碰撞、反弹、回收、比分和先手。调初速度看 `speeds` 和 `fire`，调碰撞看 `masses` 和 `collide`，调滑行衰减看 `advance`。 |

**回合边界。** `ready → moving` 只在有效出手时发生。物理以 1/120 秒固定步长推进，所有圆片停稳才重算比分并换手。若对手没有库存，当前玩家可继续；只有两边库存都空才进入 `over`。每方初始六枚，每枚最多回收三次，因此不能写死「十二发后结束」。测试计分时要区分移动中的白环与停稳后的比分。

**尺寸与资源。** 棋盘以左上为原点，高度固定为 1024；标准宽度 768，窄屏按窗口比例缩窄并等比缩放圆片。两条白区边界在 `y=171` 和 `y=853`，中线为 `y=512`。修改边界时同步检查渲染与计分，勿直接改生成的 JS。移动资源时保留同名 `.meta`；微信构建配置通过场景 UUID 引用入口，改显示名称不需要换 UUID。

## 构建和交付

在项目根目录执行：

```sh
npm run build
```

脚本会查找本机 Creator；若未找到，指定**可执行文件**（不是项目或应用目录），例如 macOS：

```sh
COCOS_CREATOR="/Applications/Cocos/Creator/3.8.6/CocosCreator.app/Contents/MacOS/CocosCreator" npm run build
```

[构建脚本](../scripts/build.cjs) 先生成 Web Mobile，再按[微信配置](../scripts/wechat-build.json)生成竖屏小游戏。Creator CLI 的成功退出码是 36，由脚本处理；两次都成功后才更新试玩入口。

| 路径 | 用途 | 版本管理约定 |
| --- | --- | --- |
| `assets/`（含 `.meta`）、`settings/`、`scripts/` | 工程源文件、项目设置和打包脚本 | 随代码提交 |
| `build/web-mobile/`、`build/wechatgame/` | Creator 的标准构建输出 | 已忽略，随时可重建 |
| `offline.html`、`wechat/` | 可直接交付的网页和小游戏；分别来自打包和复制步骤 | 随发布变更一起提交，不手改产物 |
| `library/`、`temp/`、`profiles/`、`local/` | 本机导入缓存、生成的类型与编辑器状态 | 已忽略，不要复制到其他机器 |

如只改了[离线封装脚本](../scripts/pack-offline.cjs)，已有最新的 `build/web-mobile/` 时可用 `node scripts/pack-offline.cjs` 重新封装。如果改的是 TypeScript、场景或项目设置，则需完整构建。调试标准网页可执行 `python3 -m http.server 8000 --bind 127.0.0.1 --directory build/web-mobile`，然后在本机浏览器访问 `http://127.0.0.1:8000/`；单文件试玩不需要这个服务。

微信端在开发者工具导入 `wechat/`。默认 `touristappid` 供本机调试，真机预览使用自己的小游戏 AppID。不要提交个人工具配置（`project.private.config.json` 已忽略）。构建只按文件复制，不清除交付目录中已有的多余文件；移除资源后应对照 `build/wechatgame/` 检查，保留自己的本地配置。

## 提交前如何验收

目前没有配置 `npm test`。修改手势、物理或发布流程后，至少手动走一遍：

1. **离线启动：** 关闭网络，重新打开根目录的 `offline.html`。应看到红蓝棋盘和蓝方发射光圈，而不是浏览器请求本机服务器。
2. **输入与适配：** 蓝方由下向上滑动，红方由上向下滑动。点击不动不耗子；同样距离的快滑应比慢滑更远。换窄屏后圆片仍为正圆，点位应跟手。
3. **得分与回收：** 蓝片停在上半蓝区得一分，撞出后下一次停稳应扣分。把棋子打过对方端线，对方库存应增加，而非给自己加分。
4. **结算：** 打完双方队列，确认胜负或平局；轻触重开后比分归零、红方先手。游戏中从角落打开帮助，轻触可回到原对局。
5. **微信交付：** 从新构建的 `wechat/` 编译，在模拟器检查竖屏、首帧和换手。若要作为真机可用版本交付，再用真机验证触屏、切后台返回和系统胶囊是否遮挡；浏览器通过不能代替这一步。

## 常见问题

- **提示找不到 Creator：** 检查 `COCOS_CREATOR` 指向的文件存在且可执行；无需全局安装 npm 构建工具。
- **编辑器提示缺少 `temp/tsconfig.cocos.json`：** 先让 Creator 从仓库根目录打开并完成导入。该文件由引擎生成，不要从别的项目手抄。
- **改了代码，试玩页还是旧版：** 编辑器预览读取源码，单文件与微信目录读取上一次交付产物。确认完整构建成功，重新打开新路径的网页或重新编译微信项目。
- **从哪里看构建故障：** 先看命令行第一条失败信息，再看 `temp/builder/log/` 对应平台日志。导入微信时应选择含 `game.js` 和 `project.config.json` 的目录。
