# olo-like 开发指南

## 第一次运行

只想玩不必安装开发环境：[离线试玩页](../offline.html) 已内嵌 Cocos 引擎、脚本和场景。修改游戏则用 **Creator 3.8.6 打开仓库根目录**，等资源导入完毕，再打开 [Game.scene](../assets/Game.scene)。场景里的棋盘、摄像机和圆片在运行时创建，看效果请点击预览。改名或移动目录后，需要在 Creator 或微信开发者工具中按新路径重新导入。

构建需要 Node.js 和 npm（本项目验证环境为 Node.js 22），没有需单独安装的 npm 依赖。微信开发者工具只用于导入和调试微信包，不是网页构建的前置条件。

## 一次出手经过哪些代码

| 位置 | 职责与修改入口 |
| --- | --- |
| [GameScene.ts](../assets/scripts/GameScene.ts) | 创建正交相机与棋盘节点，将触摸位置换算为棋盘坐标；将画圆、画矩形和文字指令转换为 Cocos Graphics / Label，并处理窗口变更、前后台和触摸取消。 |
| [Table.ts](../assets/scripts/Table.ts) | 主菜单与对局流转、暂停、连续多局比分、结算及记录。菜单的「双人」创建一组新的本地双人对局。 |
| [Arena.ts](../assets/scripts/Arena.ts) | 管理选子、拖动、发射和棋盘绘制。[LaunchDrag.ts](../assets/scripts/LaunchDrag.ts) 保留手指与球心的接触偏移，从松手前连续向前的轨迹计算力度，并用末段方向发射。出手路径被场上圆片挡住时，待发球会停在首次接触点。持球时将整个圆片限制在己方白区。有效前推让圆片前缘到达内侧边线时，按触摸轨迹与边线的交点出手。前推距离达到棋盘高度的 27% 即为满力，手速和按住等待的时间都不影响力度。球在边线处立即开始滚动。同一次手势继续顺势向前时，按完整推距计算力度，扣除球已经滑过的距离。出手方向固定，转向、松手或碰撞都会结束这次加力。白区内提前松手也按同一推距曲线发射。上下镜像的单色小圆点只显示后备子。 |
| [Profile.ts](../assets/scripts/Profile.ts) / [TouchAudio.ts](../assets/scripts/TouchAudio.ts) | Cocos 本地存储保存偏好和战绩。音乐与音效由浏览器或微信 Web Audio 在设备上合成。微信小游戏加载主菜单时尝试播放，浏览器在首个手势时启用声音。切后台时停声。 |
| [Match.ts](../assets/scripts/Match.ts) | 不依赖 Cocos。管理双方队列、发射、碰撞、反弹、回收、比分和先手。调初速度看 `speeds` 和 `fire`，调碰撞看 `masses` 和 `collide`，调滑行衰减看 `advance`。 |

**回合边界。** 有效出手后进入 `moving`，物理以 1/120 秒固定步长推进。上下两条白区的内侧分界线可以自由穿过，棋盘四条外边缘按球半径反弹。贴球出手时先在接触点按双方质量及碰撞方向交换冲量，再推进第一个物理步。已经在白区停住的球仍参与碰撞。最后一枚球停稳时，`Match.settleTurn` 按所有球的最终位置一次性更新比分、库存和淘汰状态，再决定换手或结束。若对手没有库存，当前玩家可继续。两边结算后都没有库存时才进入 `over`。

**微信胶囊避让。** [BoardLayout.ts](../assets/scripts/BoardLayout.ts) 让棋盘铺满微信窗口宽度。每端白区以屏高的 14% 为目标，按胶囊下沿、4 个逻辑像素的间距、库存点击范围和最大球外圈计算所需高度。空间紧时收拢光环，上下操作行镜像。确定白区边界后，再将待发球、库存与当局比分一起向各自屏幕端平移 8 个逻辑像素。换球触区和回收落点跟随库存行。在进入对局和窗口尺寸变化时计算布局。

**切屏与暂停。** [BoardTransition.ts](../assets/scripts/BoardTransition.ts) 沿棋盘中线裁切并平移两半。进场、暂停、恢复、结算、下一局和退回菜单共用进场的 0.56 秒位移曲线。棋盘的褪色和恢复也跟随同一进度。暂停后中央色带占屏高三分之一。切屏期间 `Table` 驱动动画，暂停物理、效果计时和拖动输入。开局先合拢，再由 `Arena` 播放准备球入场。中线两侧各 28 个设计单位内可起手，上拉和下拉都能打开棋盘。越过 6 个单位的触控容差后，棋盘跟手分开并冻结物理。继续拉开 42 个单位再松手即暂停，短拉或触摸中断会合拢并恢复。暂停时可从开口上下两沿中央的滑块向中线合拢，松手后沿剩余距离完成动画，再恢复物理。浏览器返回、Esc 和切后台也能暂停。暂停后再次收到返回键事件时，微信端调用 `wx.exitMiniProgram`，离线网页回主菜单。微信手机客户端的系统返回由宿主管理，`onHide` 只能在退后台时冻结对局。[微信小游戏生命周期文档](https://developers.weixin.qq.com/minigame/dev/api/base/app/life-cycle/wx.onHide.html)

**连续对局。** `Table` 在每局全场停稳且库存耗尽时记录一次本局分和胜局，平局双方都不加胜局。结算页两端的大数字显示本局分，角落显示各自的累计胜局。[PlayerColors.ts](../assets/scripts/PlayerColors.ts) 为每组新对局从四种颜色中无放回抽取两色，按固定座位分配。「继续」保留颜色和胜局并轮换先手，「菜单」结束本组。设备历史战绩单独由 `Profile` 保存。

**出球和反馈。** `Arena` 在开局、换手或换子时让待发球从玩家一端滑入，落位后接受拖动。`Match` 为每次发射记录是否离开己方白区，以及是否发生过球间碰撞或撞边。出手时振动，球心首次越过己方白区边线时播放发射音，音量和音高沿用出手力度和球的尺寸。全场停稳后，始终没离开本方发射区且没有碰撞的球触发 `misfire`，原地开裂为六块同色碎片，分离时播放约 0.19 秒的滤波噪声音效。其余停在己方白区的球触发 `return`，带光环飞回库存并播放上行音。停在对方白区触发 `capture`，变为接收方颜色再飞入其库存，伴随先降后升的滑音。复用次数不影响结算。库存飞行动画用圆片 ID 对应落点，动画完成后开放下一次输入或展示结算。进入对局时停止菜单背景音乐，退出对局回到菜单后恢复。音乐和事件音效可分别调节。

**尺寸与资源。** 棋盘以左上为原点，高度固定为 1024；标准宽度 768，窄屏按窗口比例缩窄并等比缩放圆片。离线默认两条白区边界在 `y=171` 和 `y=853`，中线为 `y=512`。修改边界时同步检查渲染与计分，勿直接改生成的 JS。移动资源时保留同名 `.meta`；微信构建配置通过场景 UUID 引用入口，改显示名称不需要换 UUID。

## 构建和交付

在项目根目录执行：

```sh
npm run build
```

脚本会查找本机 Creator；若未找到，指定**可执行文件**（不是项目或应用目录），例如 macOS：

```sh
COCOS_CREATOR="/Applications/Cocos/Creator/3.8.6/CocosCreator.app/Contents/MacOS/CocosCreator" npm run build
```

[构建脚本](../scripts/build.cjs) 先生成 Web Mobile，再按[微信配置](../scripts/wechat-build.json)生成竖屏小游戏。Creator CLI 的成功退出码是 36，由脚本处理；两次都成功后才更新试玩入口。

| 路径 | 用途 | 版本管理约定 |
| --- | --- | --- |
| `assets/`（含 `.meta`）、`settings/`、`scripts/` | 工程源文件、项目设置和打包脚本 | 随代码提交 |
| `build/web-mobile/`、`build/wechatgame/` | Creator 的标准构建输出 | 已忽略，随时可重建 |
| `offline.html`、`wechat/` | 可直接交付的网页和小游戏；分别来自打包和复制步骤 | 随发布变更一起提交，不手改产物 |
| `library/`、`temp/`、`profiles/`、`local/` | 本机导入缓存、生成的类型与编辑器状态 | 已忽略，不要复制到其他机器 |

如只改了[离线封装脚本](../scripts/pack-offline.cjs)，已有最新的 `build/web-mobile/` 时可用 `node scripts/pack-offline.cjs` 重新封装。如果改的是 TypeScript、场景或项目设置，则需完整构建。调试标准网页可执行 `python3 -m http.server 8000 --bind 127.0.0.1 --directory build/web-mobile`，然后在本机浏览器访问 `http://127.0.0.1:8000/`；单文件试玩不需要这个服务。

微信端在开发者工具导入 `wechat/`。默认 `touristappid` 供本机调试，真机预览使用自己的小游戏 AppID。不要提交个人工具配置（`project.private.config.json` 已忽略）。构建只按文件复制，不清除交付目录中已有的多余文件；移除资源后应对照 `build/wechatgame/` 检查，保留自己的本地配置。

## 提交前如何验收

在项目根目录用 Node.js 22.13 或更新版本执行 `npm test`，覆盖两端反弹、全场停稳后结算以及白区静止球被再次撞出的情况。修改手势、物理或发布流程后也要走一遍以下流程。

1. **离线启动：** 断网打开 `offline.html`，主菜单背景应在四种棋盘浅色间渐变。首次点击菜单空白处后应播放菜单音乐，已有存档时按保存的设置播放。点击「双人」进入对局时，菜单音乐应停止。
2. **输入与适配：** 按住球左右摆位，再直推或斜推，检查出手位置和方向。相同的最后一推应有相同力度，横移、短拖、反向拖或取消都不耗子。确认没有方向线、力度百分比、角落暂停热区或回合文案。切后台再返回，棋子位置与回合应保留。
3. **得分与回收。** 从两端分别打一发能到达对面端线的球。观察它穿过白区、撞边反弹，力度足够时能弹回彩色区得分。再让一枚球先停在白区，另一枚继续滑行。最后一枚球停稳时才应播放回收、夺取或销毁反馈并更新库存。
4. **结算与存储。** 连打两局，让双方各赢一局，总胜应从 1:0 变为 1:1。平局保持总胜，回菜单再开局从 0:0 起算。未完成局不计入设备战绩。滑行中触发一次返回，确认棋盘停住并分开，点「继续」后应从相同位置接着滑行。
5. **微信交付：** 从新构建的 `wechat/` 编译，在模拟器检查竖屏、首帧和换手。若要作为真机可用版本交付，再用真机验证触屏、切后台返回和系统胶囊是否遮挡；浏览器通过不能代替这一步。

## 常见问题

- **微信开发者工具提示 `libVersion` 字段错误。** 该字段填写基础库版本，例如 `"3.18.0"`。项目在[微信构建模板](../build-templates/wechatgame/project.config.json)中指定版本，修改后重新构建，再在开发者工具中编译。
- **提示找不到 Creator：** 检查 `COCOS_CREATOR` 指向的文件存在且可执行；无需全局安装 npm 构建工具。
- **编辑器提示缺少 `temp/tsconfig.cocos.json`：** 先让 Creator 从仓库根目录打开并完成导入。该文件由引擎生成，不要从别的项目手抄。
- **改了代码，试玩页还是旧版：** 编辑器预览读取源码，单文件与微信目录读取上一次交付产物。确认完整构建成功，重新打开新路径的网页或重新编译微信项目。
- **从哪里看构建故障：** 先看命令行第一条失败信息，再看 `temp/builder/log/` 对应平台日志。导入微信时应选择含 `game.js` 和 `project.config.json` 的目录。
